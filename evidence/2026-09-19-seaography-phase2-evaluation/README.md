Status: done. Continues `GSR-PHASE-2` after `evidence/2026-09-19-seaography-phase2-administration/`
(and `.../phase2-configuration/`); covers file 8 of 13, the largest ported so far (1250 static-tier

## What this step built

- `crates/hive-api/src/graphql_schema/scalars.rs`: a new `wire_enum!` macro hand-rolling
  `CustomOutputType`/`CustomInputType` for a plain, unit-variant-only enum, plus a
  `WireEnumFixture` test proving a real enum round-trips through a throwaway schema (SDL printing
  and both directions of value parsing) before any production enum used it. `mod.rs::build()`
  registers the `Long` scalar (evaluation.rs is the first production module to use it) the same way
  `agent.rs` needed for `JSON`.
- `crates/hive-api/src/graphql_schema/evaluation.rs`: 3 GraphQL enums (`EvaluationTargetKind`,
  `EvaluationRunStatus`, `EvaluationOutcomeCategory`), the sixth interface this port builds
  (`EvaluationProblem`, 8 implementors — the most yet), 8 connection/edge type pairs generated by a
  local `connection_type!`/`from_app_connection!` macro pair (directly mirroring the static tier's
  own macros of the same names), the complex `EvaluationRun` (4 lazily-resolved nested connection
  fields: `cases`/`metrics`/`artifacts`/`audit`, each `(after: String, first: Int! = 50)`), 9 input
  types, 9 queries, and 8 mutations.

## What this step found

**`#[derive(CustomEnum)]` only builds the enum's own type definition, not the two traits a field or
argument actually needs.** Read `custom_enum.rs` before writing any enum code (not after hitting a
failure, unlike most of this port's findings): it generates `impl CustomEnum { fn to_enum() -> Enum
{ ... } }` only, feeding `register_custom_enum` the same way `register_custom_output`/
`register_custom_input` work for structs — no blanket impl bridges `CustomEnum` to
`CustomOutputType`/`CustomInputType`. Confirmed by grepping the entire seaography source for any
such bridge; none exists. `scalars::wire_enum!` hand-rolls both, mirroring `custom/output.rs`'s and
`custom/input.rs`'s own patterns for a value-only field (`FieldValue::value(Value::Enum(Name))` /
`ValueAccessor::enum_name()`).

**Enum variant identifiers must be spelled in full SCREAMING_SNAKE_CASE, not Rust-idiomatic
UpperCamelCase.** `#[derive(CustomEnum)]`'s codegen uses `stringify!(variant_ident)` verbatim
(confirmed by reading `custom_enum.rs`, not assumed), and the frozen contract's own enum values are
SCREAMING_SNAKE_CASE (`AGENT_VERSION`, `QUEUED`, `PASSED`, ...; checked against
`schema/contract.graphql` before writing any variant name). Rust variants are therefore named
`AGENT_VERSION`/`QUEUED`/etc. verbatim, inside `#[allow(non_camel_case_types)]` — the same
`GSR-WIRE-CASE` discipline this whole port already applies to methods/fields/struct names, just
extended to enum variants. This also trips `clippy::upper_case_acronyms` (a real lint in general,
but a false positive here — the spelling is the wire contract, not a stylistic lapse), suppressed
with `#[allow(clippy::upper_case_acronyms)]` and a comment, following the same precedent
`agent.rs`'s `#[allow(clippy::enum_variant_names)]` set.

No other new defects surfaced. The `Vec<String>`/`StringList` and keyword-collision-shaped findings
from earlier files didn't recur (no `Vec<String>` fields other than `path`, already handled;
no keyword-named fields), and the `Long` scalar's registration gap was anticipated and pre-empted
(recorded in the design doc back when `JSON`'s gap was found) rather than rediscovered by a second
panic.

## Verification

Same methodology as every prior slice: `hive schema-sdl --engine dynamic`'s output (dangling
`schema { ... subscription: Subscription }` block stripped) compared against
`schema/contract.graphql` using `describe()`/`assert.deepEqual()`. All 49 new types (3 enums + 46
object/input types) and 17 new root fields (9 queries, 8 mutations) match the frozen contract
exactly, `EvaluationRun`'s 4 nested fields match including their `first: Int! = 50` defaults, and
all 8 `EvaluationProblem` implementors are confirmed to declare the interface. Full run in
`dynamic-sdl-parity.log`.
