# Code Comments

Write clear comments and docstrings for non-obvious behavior, constraints, or intent that readers need to use or change the code correctly. Follow existing API documentation conventions. Omit comments that restate the code, narrate the change, or preserve commented-out code.

State the technical reason directly. Keep tickets, tasks, pull requests, documents, URLs, standards, and requirement identifiers out of comments, docstrings, and symbol names; repository symbols and code paths are allowed. Name symbols for their behavior or role. This rule does not require creating a commit, issue, or supporting document.

Preserve license headers and tool directives.
