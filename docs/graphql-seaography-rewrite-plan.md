# GraphQL and Persistence Rewrite onto Seaography and SeaORM

Status: **complete** (September 20, 2026). All nine phases (`GSR-PHASE-0` through `GSR-PHASE-P8`)
are done; every defect and scope correction found along the way is recorded in place below and in
each phase's own `evidence/` directory. The static async-graphql schema is deleted, every
`hive-persistence` repository runs on `sea_orm`, and `sqlx` is gone from every crate's production
`[dependencies]` (kept only in two crates' `[dev-dependencies]` for their own test-fixture helpers,
per `GSR-PHASE-P8`'s scope correction). Full `validate:local` (49 checks) passed clean against the
final commit; see `evidence/2026-09-20-seaography-phase8-audit-closure/`.

## Purpose

[The transformation design](./rust-transformation-design.md) fixed the target architecture in its decision summary: "Seaography supplies the generated-read tier and the composition mechanism; async-graphql `#[CustomFields]` implementations supply the custom tier; SeaORM supplies the entity model and the normalized reads." The implementation that landed did neither. `crates/hive-api/src/schema/` (13 files, 6,521 lines, 74 console-facing operations) is a static async-graphql schema built from `#[Object]`, `#[derive(SimpleObject)]`, `#[derive(Enum)]`, `#[derive(InputObject)]`, `#[derive(Interface)]` and `#[derive(MergedObject)]`, composed at `crates/hive-api/src/schema/mod.rs:93` as `Schema<RootQuery, RootMutation, EmptySubscription>`; `crates/hive-persistence/` (21,852 lines) is hand-written `sqlx` with positional `row.get(n)` decoding (`RIDR-FROM-ROW`); `sea-orm` is declared in the workspace and consumed by nothing (`RIDR-SEA-ORM-DEAD-DEPENDENCY`); `seaography` was never added. The design's own status section records this: "`RTD-GENERATED-READ-TIER` was never built."

This plan specifies the full rewrite. Seaography becomes the composition mechanism for the whole GraphQL layer and SeaORM becomes the first-class mechanism for all database access, reads and writes, including the aggregate repositories the original design had exempted as verbatim SQL. The static-macro schema code and the `sqlx` repository code are deleted at the end of the phases that replace them; nothing is kept alongside indefinitely. The console contract (`schema/console-operations/*.graphql`, `schema/contract.graphql`, `npm run check:schema:contract`) does not change by a single field, argument, default, nullability, or type name.

Requirements carry immutable identifiers of the form `GSR-<SLUG>`. Where this plan revises a design-document decision, it names the `RTD-*` identifier it revises.

## Verified facts about the real crates

Every decision below rests on one of these facts; each names the file that settles it. Prior assumptions about Seaography's API from documentation or training data were not used.

`GSR-FACT-BUILDER`: `seaography::Builder::new(context: &'static BuilderContext, connection: sea_orm::DatabaseConnection)` creates `Object::new("Query")`, `Object::new("Mutation")` pre-loaded with a `_ping: String` field, and a `Subscription`; `register_custom_query::<T: CustomFields>()` and `register_custom_mutation` append `T::to_fields(context)` to the public `queries`/`mutations: Vec<Field>`; `register_custom_output::<T: CustomOutputObject>()` pushes `T::basic_object(ctx)` to the public `outputs: Vec<Object>`; `register_complex_custom_output::<T: CustomOutputObject + CustomFields>()` folds `T::to_fields` onto `T::basic_object`; `register_custom_enum`, `register_custom_union`, `register_custom_input`, `register_scalar(Scalar)` exist; `schema_builder(self) -> async_graphql::dynamic::SchemaBuilder` registers everything and additionally always registers a `Json` scalar, `OrderByEnum`, `CursorInput`, `PageInput`, `OffsetInput`, `PaginationInput`, `PageInfo`, `PaginationInfo`; `set_depth_limit(Option<usize>)`/`set_complexity_limit` map to `SchemaBuilder::limit_depth`/`limit_complexity`. With the default `schema-meta` feature it also adds a `_sea_orm_entity_metadata(table_name: String!)` query. (`seaography-2.0.0-rc.9/src/builder.rs`, `impl Builder`.)

`GSR-FACT-CUSTOMFIELDS`: `#[CustomFields] impl T { async fn f(ctx: &Context<'_>, a: A, ...) -> async_graphql::Result<R> }` generates one `async_graphql::dynamic::Field::new(stringify!(f), <R>::gql_output_type_ref(context), ...)` per method with one `InputValue::new(stringify!(a), <A>::gql_input_type_ref(context))` per argument. Names are the Rust identifiers verbatim: there is no camel-case conversion, no rename attribute, no `default_value`, no `deprecation`, no `description`. A method without `&self` becomes `Self::f(...)` (a root field); a method with `&self` downcasts `ctx.parent_value` to `Self` (an object field). The first typed argument whose type path ends in `Context` receives `ctx.ctx`, the plain `async_graphql::Context`, so `ctx.data::<X>()` works exactly as in the static resolvers. `R` must implement `seaography::CustomOutputType`; each `A` must implement `seaography::CustomInputType`. (`seaography-macros-2.0.0-rc.9/src/custom_fields.rs`, `signature_to_field`, `is_context_arg`.)

`GSR-FACT-DERIVES`: `#[derive(CustomOutputType)]` on a struct with named fields implements `CustomOutputType` (`TypeRef::named_nn(name)`, `FieldValue::owned_any(self)`) and `CustomOutputObject` (an `Object` with one `Field` per struct field named `stringify!(field_ident)`, resolved by `obj.field.clone()`); the type name is the struct identifier unless `#[seaography(output_type_name = "...")]`. On an all-unit enum it emits `Value::Enum(variant_ident)`; on an all-container enum it implements `CustomUnion` and `CustomOutputType` with `FieldValue::owned_any(inner).with_type(variant_ident)`, and requires every variant's identifier to equal its single unnamed field's type identifier (`util.rs`, `parse_enum_variants`). `#[derive(CustomInputType)]` on a struct names the input `{Ident}Input` unless `#[seaography(input_type_name = "...")]`, parses each field with `<Ty>::parse_value(context, input_object.get(stringify!(field)))`. `#[derive(CustomEnum)]` emits `Enum::new(name).item(stringify!(variant))` per variant. `Option<T>` strips one `NonNull`; `Vec<T>` is `[T]!`. The blanket scalar impls exist for `bool`, the integer and float primitives, `String`, `serde_json::Value` (as type `Json`, non-null), and, behind `with-uuid`/`with-chrono`, `Uuid` and the chrono types. There is no impl for `async_graphql::ID`. (`custom_output_type.rs`, `custom_input_type.rs`, `custom_enum.rs`, `seaography-2.0.0-rc.9/src/custom/aux_types.rs`, `src/custom/output.rs`.)

`GSR-FACT-NO-INTERFACE`: Seaography defines `CustomFields`, `CustomOutputType`, `CustomOutputObject`, `CustomInputType`, `CustomInputObject`, `CustomEnum`, `CustomUnion` and nothing for interfaces (`src/custom/types.rs`, `output.rs`, `input.rs`). `async_graphql::dynamic::Interface::new(name).field(InterfaceField::new(name, TypeRef))`, `Object::implement(interface_name)`, `From<Interface> for Type` and `SchemaBuilder::register(impl Into<Type>)` all exist in async-graphql 7.0.19 (`src/dynamic/interface.rs:161-196`, `object.rs:99`, `type.rs:153`, `schema.rs:42`), and the executor resolves an interface-typed value through `FieldValueInner::WithType { value, ty }` exactly as it resolves a union (`src/dynamic/resolve.rs:549-560`).

`GSR-FACT-DEFAULTS`: `async_graphql::dynamic::InputValue::default_value(impl Into<Value>)` and `Field::deprecation(Option<&str>)` exist (`src/dynamic/input_value.rs:45`, `field.rs:381`); `Field.arguments`, `Field.name`, `Object.fields` are `pub(crate)`, so a `Field` produced by `#[CustomFields]` cannot be amended afterwards. A `Field` needing a default or a deprecation must be constructed directly.

`GSR-FACT-NULL`: a `None` returned for a `NonNull` field yields the error `internal: non-null types require a return value` (`src/dynamic/resolve.rs:418-420`), positioned at the field and nulling the nearest nullable ancestor, which is the same propagation the static `Required<T>` (`crates/hive-api/src/schema/required.rs`) relies on with a different message.

`GSR-FACT-PAGEINFO`: Seaography's always-registered `PageInfo` object has `hasPreviousPage: Boolean!`, `hasNextPage: Boolean!`, `startCursor: String`, `endCursor: String` (`src/outputs/page_info_object.rs`) — field-for-field the contract's `type PageInfo` (`schema/contract.graphql:1751-1756`) — and the `seaography::PageInfo` struct already implements `CustomOutputType` (`src/custom/output.rs`).

`GSR-FACT-ENTITY-NAMES`: for a registered entity Seaography names the object `context.entity_object.type_name(table_name)` (default `UpperCamelCase` of the SeaORM table name), the root connection field `to_lower_camel_case(object_name)` (`src/query/entity_query_field.rs`, `type_name_vanilla`), and the companions `{Object}Edge`, `{Object}Connection`, `{Object}FilterInput`, `{Object}OrderInput`, `{Object}HavingInput`; `pluralize_unique` is the identity without the `field-pluralize` feature (`src/utilities.rs:313`). Column fields are `lowerCamelCase`; `uuid` columns map to `String`, `bigint` to `Int`, `jsonb` to the `Json` scalar (`src/builder_context/types_map.rs`). The root connection resolver calls `hooks.entity_guard`, then `hooks.entity_filter`, reads `ctx.data::<DatabaseConnection>()`, and applies `.restricted(ctx.data_opt::<UserContext>())`; relation fields call `entity_guard`, `field_guard` and `entity_filter` on the related entity too (`src/query/entity_object_relation.rs:74-95`, `entity_object_via_relation.rs:85-106`); column fields call `field_guard` (`src/outputs/entity_object.rs:161`).

## Decisions

### Composition

`GSR-DYNAMIC-SCHEMA`: the runtime schema is a `seaography::Builder` composition and nothing else. `crates/hive-api/src/graphql_schema/mod.rs` (new; the name avoids colliding with `schema/` during the switch period) owns one `static CONTEXT: LazyLock<BuilderContext>` and one `pub fn build(db: DatabaseConnection) -> async_graphql::dynamic::Schema`. The function registers, in this order: the three read entities (`GSR-READ-TIER`), the three scalars (`GSR-SCALARS`), every enum, every input, every plain output, every complex output, the seven interfaces (`GSR-INTERFACES`), one `register_custom_query` per feature bundle (`CoreQueries`, `OrganizationQueries`, `ProjectQueries`, `ConsoleQueries`, `AdministrationQueries`, `AgentQueries`, `ConfigurationQueries`, `DeploymentQueries`, `EvaluationQueries`, `AuditQueries`), one `register_custom_mutation` per mutation bundle (`ConsoleMutations`, `AdministrationMutations`, `AgentMutations`, `ConfigurationMutations`, `DeploymentMutations`, `EvaluationMutations`), the hand-built fields (`GSR-DEFAULTS`), then `set_depth_limit(Some(20)).set_complexity_limit(Some(500)).schema_builder().data(db).finish()`. `register_entity_mutations` is never called (schema governance "default deny"; `RTD-TENANT-HOOKS` `entity_guard` denies writes as defense in depth). `seaography` is declared with `default-features = false, features = ["macros", "with-uuid", "with-chrono", "with-json", "field-camel-case"]` so `schema-meta` does not add `_sea_orm_entity_metadata`. The `_ping` mutation and `Json` scalar the Builder adds unconditionally are accepted: neither is reachable from any console document, so `check:schema:contract` does not compare them (its `reachableTypes()` walks only from the root fields the documents select).

`GSR-WIRE-CASE`: because Seaography emits names verbatim (`GSR-FACT-CUSTOMFIELDS`, `GSR-FACT-DERIVES`), every Rust identifier that becomes a GraphQL name is spelled in wire case: struct fields and method names in `lowerCamelCase` (`displayName`, `lifecycleStatus`, `accessibleOrganizations`), method arguments in `lowerCamelCase` (`organizationId`, `includeTotalCount`), enum variants exactly as the SDL spells them (`DEVELOPMENT_LOW`, `PENDING`), type names as today. `crates/hive-api/src/graphql_schema/mod.rs` carries `#![allow(non_snake_case, non_camel_case_types)]`; `cargo clippy -D warnings` stays green. Input structs whose contract name already ends in `Input` (every `Create*Input`, `Update*Input`, `*Filter`, `AuditEventFilter`, `AccessibleOrganizationsFilter`, `OrganizationProjectFilter`, `AgentDirectoryFilter`) carry `#[seaography(input_type_name = "<exact contract name>")]` because the derive would otherwise emit `CreateProjectInputInput`. The static layer's `#[graphql(name = ...)]` renames (`administration.rs:578-594` enum values, `audit.rs:24` the field `type`) are realized by spelling; the one field named `type` is a Rust keyword and `stringify!(r#type)` yields `r#type`, so `AuditResourceReference` is one of the hand-built objects in `GSR-DEFAULTS`.

`GSR-SCALARS`: `crates/hive-api/src/graphql_schema/scalars.rs` defines three newtypes and implements `seaography::CustomOutputType` and `CustomInputType` for each by hand (the only hand-written trait impls in the tier; the orphan rule forbids implementing Seaography's traits on `async_graphql::ID`): `Id(String)` → `TypeRef::named_nn(TypeRef::ID)` / `Value::String`, parsing `ValueAccessor::string()`; `Long(i64)` → `TypeRef::named_nn("Long")`, serializing `Value::Number`, parsing a number or a numeric string exactly as `long.rs` does today (`RTD-SCALAR-SERIALIZATION`); `Json(serde_json::Value)` → `TypeRef::named_nn("JSON")`. `build()` calls `builder.register_scalar(Scalar::new("Long").description("A signed 64-bit integer."))` and `register_scalar(Scalar::new("JSON").description("A structured JSON value."))` — those two descriptions are the only ones on console-reachable types (baseline), and `check:schema:contract`'s `compareDescriptions` requires them. `Option<Id>` etc. compose through Seaography's blanket `Option`/`Vec` impls. Seaography's own `Json` scalar (capital J only) coexists unreached. `crates/hive-api/src/schema/long.rs` and the `Json` newtype in `schema/agent.rs` are deleted with the static tier.

`GSR-REQUIRED`: `scalars.rs` also carries `Required<T>(Option<T>)` with `impl<T: CustomOutputType> CustomOutputType for Required<T>`: `gql_output_type_ref` wraps `T`'s ref in `TypeRef::NonNull` when it is not already; `gql_field_value` returns `self.0.and_then(|v| T::gql_field_value(v, ctx))`. A missing value therefore produces the engine's `internal: non-null types require a return value` error with the same null propagation as today's `required.rs`. The message differs from the static `The field ... was declared as a non null type, but no value is recorded.`; no harness script or integration test asserts either text (`grep -rn "declared as a non null" crates/hive-api/tests scripts` is empty), and this is recorded in [Risks](#risks).

`GSR-INTERFACES`: the seven interfaces `AdministrationProblem`, `AgentDraftProblem`, `ConfigurationProblem`, `DeploymentApprovalProblem`, `DeploymentProblem`, `DisplayPreferencesProblem`, `EvaluationProblem` are built with `async_graphql::dynamic::Interface::new(name).field(InterfaceField::new("code", TypeRef::named_nn(TypeRef::STRING))).field(InterfaceField::new("message", ...))` in `crates/hive-api/src/graphql_schema/problems.rs` and registered on the `SchemaBuilder` after `schema_builder()` (`.register(interface)`), since `Builder` has no interface vector. Each Rust problem enum keeps its name and derives `CustomOutputType` as a container enum with variants renamed to the concrete type names, for example `pub enum AdministrationProblem { AdministrationNotFoundProblem(AdministrationNotFoundProblem), AdministrationAuthorizationProblem(...), ... }`; the derive's `CustomUnion` impl is generated but `register_custom_union` is never called for it, so the name resolves to the interface. Each concrete problem struct derives `CustomOutputType` and is pushed as `builder.outputs.push(X::basic_object(&CONTEXT).implement("AdministrationProblem"))` instead of through `register_custom_output`, because `implement` must be applied to the `Object`. `check:schema:contract` compares `interfaces` per object and `kind: "interface"` per interface; both are satisfied. The `From<App*Problem>` conversions keep their bodies with the new variant names.

`GSR-DEFAULTS`: the 20 fields whose SDL carries something `#[CustomFields]` cannot emit are built directly with `async_graphql::dynamic::Field` in `crates/hive-api/src/graphql_schema/<domain>.rs` and pushed to `builder.queries` (root) or folded onto the owning `Object` before it is pushed to `builder.outputs` (nested), each delegating to the same `async fn` the bundle would otherwise expose. Root: `accessibleOrganizations(first: Int = 50)`, `approvalInbox(first: Int! = 20)`, `auditEvents(first: Int = 25, includeTotalCount: Boolean = false)`, `deploymentEnvironmentDefinitionVersions(first: Int! = 20)`, `deploymentProjection(first: Int! = 20)`, `deploymentTimeline(first: Int! = 20)` plus `.deprecation(Some("Use deploymentProjection for the detail and timeline from an authorized projection."))`, `deployments(first: Int! = 20)`, `evaluationDefinitionVersionUsage(first: Int! = 50)`, `evaluationDefinitionVersions(first: Int! = 50)`, `evaluationDefinitions(first: Int! = 50)`, `evaluationRuns(first: Int! = 50)`, `evaluationTargets(first: Int! = 50)`. Nested: `Organization.projects(first: Int = 25)`, `Project.agents(first: Int = 25)`, `ApprovalRequirement.decisions(first: Int! = 20)`, `EvaluationRun.cases|metrics|artifacts|audit(first: Int! = 50)`. Also hand-built: `AuditResourceReference` (field `type`, `GSR-WIRE-CASE`) and the input object `AccessibleOrganizationsFilter` (field `includeArchived: Boolean = false`, today's `#[graphql(default_with = "Some(false)")]` at `organization.rs:144`; `InputObject::field(InputValue::default_value(...))`). Argument parsing inside these hand-built resolvers uses the same `<T as CustomInputType>::parse_value(&CONTEXT, ctx.args.get(name))` the macro generates, so coercion is identical. A unit test in `graphql_schema/tests.rs` asserts that the set of hand-built field names equals this list, so the exception cannot grow silently.

`GSR-NESTED-FIELDS`: the four output types with resolver-backed fields — `Organization` (`projects`), `Project` (`agents`), `EvaluationRun` (`cases`, `metrics`, `artifacts`, `audit`), `ApprovalRequirement` (`decisions`) — derive `CustomOutputType` for their data fields and are registered through `register_complex_custom_output::<T>()`, with the resolver-backed field(s) added per `GSR-DEFAULTS` (all five carry defaults). `ApprovalRequirement.decision_preview` (today `#[graphql(skip)]`, `deployment.rs:1165`) moves out of the struct into a private sibling type `ApprovalRequirementPreview` held by `ApprovalInboxItem` and passed to the `decisions` resolver through the parent value; the derive exposes every field, so nothing that must stay hidden may live on a derived struct.

`GSR-OCC`: the concurrency semantics the repositories implement today are preserved statement for statement: a locked read (`lock_exclusive`, `lock_shared`, `KeyShare`) is issued at the same point in the same transaction; a revision-predicated update maps `RecordNotUpdated` to the same typed conflict; a commit that fails with SQLSTATE `40001` (Aurora DSQL commit-time optimistic-concurrency failure, `sql.rs`'s comment) is caught from `DatabaseTransaction::commit()` and mapped to the same retry or `REVISION_CONFLICT` branch; `23505` maps through `SqlErr::UniqueConstraintViolation`. ### Sequencing

`GSR-SWITCH`: the GraphQL tier is built in parallel and switched atomically, mirroring `LFP-SWITCH`. From `GSR-PHASE-1` the crate has both `crates/hive-api/src/schema/` (static, frozen — no edits except constructor arguments changed by the persistence phases) and `crates/hive-api/src/graphql_schema/` (dynamic). `AppState.schema` becomes `enum HiveSchema { Static(async_graphql::Schema<..>), Dynamic(async_graphql::dynamic::Schema) }` with `execute` and `sdl` delegating; `HIVE_GRAPHQL_ENGINE=static|dynamic` (default `static`) selects it in `state_from_env`, and `hive schema-sdl --engine <static|dynamic>` (default from the same variable) prints either. `scripts/schema-contract.mjs` gains an `HIVE_GRAPHQL_ENGINE` passthrough and, until the switch, `check:schema:contract` runs twice (`static`, then `dynamic`) — the second run is allowed to fail until `GSR-PHASE-3`'s gate. `scripts/local-service.mjs` forwards `HIVE_GRAPHQL_ENGINE` to every fixture so every `check:integration:*`/`check:e2e:*` can run against the dynamic engine. The static engine is deleted in `GSR-PHASE-4` in one commit, exactly as `web/` was. The persistence rewrite is sequenced per repository behind the port traits and does not need a flag: each ported repository replaces the old one in the same commit its gate passes.

The reason for one atomic GraphQL switch rather than a per-domain cutover is structural: a `dynamic::Schema` and a static `Schema<Q, M, S>` cannot share one `Query` root, and `/graphql` serves one schema, so per-domain would mean routing requests by operation name to two engines — a transport behavior the contract does not have and the harness would not cover. The parallel-build-then-switch pattern has precedent in this repository and was gated by the same harness.

## Persistence rewrite: module by module

Order is dependency order; each module's replacement is described so it can be implemented from this text. Every module ends with its old `sqlx` file(s) deleted in the same commit.

1. `connection.rs` → `DatabaseConnection` factory (`GSR-CONNECTION`). Gate: `check:rust`, `check:rust:database` (the `migrator_integration` test migrates through the new connection).
2. `migrator/{mod,sql,steps}.rs` → statements run through `ConnectionTrait::execute_unprepared` on `DatabaseConnection`; ledger rows (`hive_schema_migrations`, `hive_schema_migration_lock`) become entity modules with `ActiveModel` inserts; `RTD-LEDGER-COMPAT` behavior unchanged. Gate: `cargo test -p hive-persistence --test migrator_integration -- --ignored` (30 ledger rows, idempotent replay).
3. `entity/` (76 + 1 + 3 modules) with `tenant::condition` (`GSR-ENTITY-ALL`, `GSR-TENANT-HOOKS`). Gate: `check:schema:entity-coverage`, `check:schema:entity-relations`.
4. `capability/{mod,queries,tx,locks}.rs` → one generic `async fn has_capability<C: ConnectionTrait>(db: &C, principal, capability, scope, lock: bool)`; the `queries.rs`/`tx.rs` duplication (kept today only because `sqlx` executors would not genericize) collapses to one implementation; `locks.rs` becomes locked `Select`s with `lock_with_tables`. Gate: `cargo test -p hive-persistence --test capability_integration -- --ignored` (13 tests), `check:integration:console`.
5. `console/mod.rs` → `find_context`/`find_preferences` as `Select` joins with `FromQueryResult`; `update_preferences` as `principals::Entity::find_by_id(..).lock_exclusive().one(&txn)` then `principal_display_preferences::ActiveModel` upsert. Gate: `check:integration:console`, `check:e2e:console-context`.
6. `organization/{accessible_organization,overview,project_directory}.rs`, `project/dashboard.rs`, `agent/{project_agent_directory,operational_view}.rs` → keyset-paginated `Select`s with `Condition` built from the existing cursor decoders (cursors are pure and stay), `total_count` via `count()`; `LATERAL` and `UNION` cases through `SelectStatement` + `find_by_statement`. Gate: `check:integration:organization`, `organization-overview`, `organization-project-directory`, `project-agent-list`, `project-dashboard`, `agent-operational-view`; e2e `organization-selector`, `organization-overview`, `organization-project-list`, `project-dashboard`, `project-agent-list`, `console-navigation`.
7. `administration/{mutations,queries,rows}.rs` → `DatabaseTransaction` per command; locked re-check through module 4; `ActiveModel` inserts for memberships, roles, policies, versions, audit events (with `before_save` metadata); revision updates via `UpdateOne::filter(Revision.eq(..))` → `RecordNotUpdated` → `REVISION_CONFLICT`; `set_config` per `GSR-RAW-SQL-EXCEPTIONS`. Gate: `check:integration:administration`, `check:e2e:administration-settings`, `check:e2e:organization-project-authoring`.
8. `agent/draft.rs` → same pattern; `jsonb` string lists as `Json`; the DSQL `40001`-at-commit retry loop around `txn.commit()` via `is_serialization_failure(&DbErr)`; `evaluation_target_projections` maintenance as `ActiveModel` upsert. Gate: `check:integration:agent-draft-editor`, `agent-authoring`; e2e `agent-draft-editor`, `agent-authoring`, `agent-operational-view`.
9. `configuration/{mutations,queries,rows}.rs` → same pattern. Gate: `check:integration:configuration`, `check:e2e:configuration`.
10. `deployment/{queries,writes,mutations,approval,cursors,rows,worker}.rs`, `approval_maintenance.rs`, `worker_health.rs` → the largest area (6,200 lines): `writes.rs` helpers generic over `ConnectionTrait`; outbox claim as `lock_with_behavior(Update, SkipLocked)`; heartbeats as upserts; `approval.rs`'s `transition_requirement` as `UpdateOne::filter` OCC; reconciliation loops keep one `DatabaseTransaction` per Java `setAutoCommit(false)` block and the same `commit`/`rollback` points. Gate: `check:integration:deployment`, `deployment-harness`, `approval`, `mvp-shared`; e2e `deployment`, `approval`; `/health` maintenance fields via `http_integration`.
11. `evaluation/{queries,mutations,rows,cursors,worker}.rs` → same pattern; `EvaluationWorkStore` claim/commit/failed on `DatabaseTransaction`. Gate: `check:integration:evaluation`, `check:e2e:evaluation`.
12. `audit/{mod,cursors,context}.rs` → `audit_event_projection::Entity::find()` with `Condition` from the filter and cursor, `count()` for `includeTotalCount`; `bind_audit_metadata` deleted, `context.rs` keeps `scope`/`current`. Gate: `check:integration:audit`, `audit-transaction`, `audit-plan` (the plan check asserts index usage on the view; SeaORM emits the same predicate columns, verified by phase evidence), `check:e2e:audit`.
13. `sql.rs` deleted; `get_postgres_connection_pool()` call sites zero.

| `async-graphql`'s dynamic `ObjectAccessor::get(name)` (`dynamic::value_accessor.rs`) returns `Some(ValueAccessor(Value::Null))`, not `None`, when a client passes an optional argument *explicitly* as `null` — a literal `null`, or (the case that actually surfaced this) a GraphQL variable bound to `null` — rather than omitting it; only a truly *absent* key yields `None`. Every hand-built resolver across this entire phase-2 port that read an optional argument used the pattern `ctx.args.get(name).map(\|value\| value.string()...).transpose()?`, which assumes `Some(...)` always wraps a real value — calling `.string()`/`.i64()`/`.boolean()`/`.object()` on the wrapped `Value::Null` instead, and each of those methods' own fallback arm is `Err("internal: not a string")` (or the `i64`/`boolean`/`object` equivalent), not "treat as absent". Affected essentially every nullable `after`/`before`/`filter`/`organizationId`/`projectId` argument in `organization.rs`, `project.rs`, `audit.rs`, `evaluation.rs`, and `deployment.rs` (24 call sites total) — a systemic pattern repeated across five files, not an isolated typo. Found by `check:integration:approval` (`scripts/approval-access.mjs`'s `DecisionHistory` query passing `{ after: null }` as a variable) during a full `validate:local` run after the `_ping` fix; root-caused by reading `value_accessor.rs`'s `ObjectAccessor::get`/`ValueAccessor::string()` directly, not assumed. | `check:integration:approval`; `graphql_schema::scalars::tests::optional_string_treats_an_explicit_null_argument_as_absent` (added, covers both a literal `null` and a null-valued variable) | fixed with three shared helpers in `scalars.rs` — `defined(value)` (filters `Value::Null` out of `Option<ValueAccessor>`, exposed for the `filter`-argument match arms and anywhere a value is threaded into a derived `parse_value`), `optional_string`/`optional_i64`/`optional_boolean` (apply `defined` then the matching accessor) — and every one of the 24 call sites rewritten to use them instead of the raw `.get(name).map(\|value\| value.TYPE()...)` pattern. | `GSR-PHASE-P5`'s module-4 text ("the `queries.rs`/`tx.rs` duplication ... collapses to one implementation") assumed `capability::tx.rs` (the locked, transaction-scoped duplicate) could be rewritten alongside `capability::queries.rs` in the same phase. Grepping its actual consumers found five modules calling it, not the one the phase ordering implied: `agent::draft` and `configuration::mutations` (phase P6, not yet ported), `administration::mutations` (phase P6), and `deployment::{queries,mutations}` and `evaluation::{queries,mutations}` (phase P7) — all still building their write transactions on raw `sqlx::Transaction`/`&mut PgConnection`. Rewriting `tx.rs` onto `ConnectionTrait` now would force one of two bad outcomes: pull all five modules' transaction management forward out of dependency order in the same commit, or run `tx.rs`'s locked check on a *different* physical connection than the write transaction it is supposed to share, silently breaking the row-lock-holds-until-commit guarantee the whole module exists for — a correctness regression `capability_integration`'s own tests (locked-answer-matches-unlocked-answer, run against a bare, transaction-less connection) cannot detect, since they never assert that a lock blocks a *concurrent* writer. | none today; `capability_integration`'s tests would not catch a cross-connection lock regression if one were introduced | `capability::tx.rs` is left untouched (still `sqlx`/`&mut PgConnection`) for now; each of the five consuming modules ports its own `tx::*` call sites to `sea_orm::DatabaseTransaction` inside its own phase (P6 for `agent::draft`/`configuration`/`administration`, P7 for `deployment`/`evaluation`), shrinking `tx.rs` as each lands. **Outcome, confirmed once P7 landed**: this prediction was half right. Three of `tx.rs`'s primitive helpers (`has_active_organization_role`/`has_active_project_role`/`project_organization`/`active_project`/`has_platform_admin`, plus their `_read` twins) did go fully dead once their last caller (`deployment`/`evaluation` in P7) stopped needing the hardcoded-locked/unlocked split — `capability::queries.rs`'s own equivalents (already `lock: bool`-parameterized since Phase P5) cover them exactly, and those functions were deleted. But `deployment_capabilities`/`deployment_approval_capabilities`/`has_deployment_capability`/`evaluation_capabilities`/`has_evaluation_capability` are *not* duplicates of anything in `queries.rs` — they are the deployment/evaluation capability-composition logic itself, with no other home — so `tx.rs` is not deleted at the end of P7; it is ported in place (`ConnectionTrait`-generic, composed from `capability::queries::*`) and kept permanently, the same status as `queries.rs`/`locks.rs`. Full finding in `evidence/2026-09-20-seaography-phase7-deployment-evaluation/` |

## What gets deleted

Done at `GSR-PHASE-4`: `crates/hive-api/src/schema/{administration,agent,audit,configuration,connection,console,deployment,evaluation,long,mod,organization,project,required}.rs` (all 13 files, 6,521 lines), including `RootQuery`, `RootMutation`, `CoreQueries` and every `*Queries`/`*Mutations` `#[Object]` impl, `build_schema`, the static `HiveSchema` type alias, every `#[derive(SimpleObject|Enum|InputObject|Interface)]`, `#[ComplexObject]`, `connection_type!`, `from_app_connection!`, `deployment_connection_type!`, `from_app_deployment_connection!`, `Required`, `Long`, the `Json` newtype in `agent.rs`; `engine.rs` and its `Engine`/`HiveSchema` wrapper enum, `HIVE_GRAPHQL_ENGINE`, and `--engine`; the static branch of `schema_sdl()`. `async-graphql`'s default features (static macros) were already disabled in `Cargo.toml` from `GSR-PHASE-0` onward.

At `GSR-PHASE-P5` through `P8`: every `sqlx::query*` call site (424), every `row.get(n)` decoder, `capability/locks.rs`'s duplication with `tx.rs`/`queries.rs` (the primitive functions; `tx.rs`'s own composition logic is kept, see the `GSR-PHASE-P7` row and the risk table), `audit::context::bind_audit_metadata`, `ConnectionFactory::pool`, every `PgPool`/`PgConnection` type in production code (`crates/hive-persistence/src`, `crates/hive-api/src`), the `sqlx` workspace dependency from every crate's `[dependencies]`, and `hive_api::test_state(PgPool, ..)`'s pool parameter. **Not deleted, corrected from this section's original claim** (`GSR-PHASE-P8`): `crates/hive-persistence/src/sql.rs` — `parse_string_array`/`json_array`/`is_serialization_failure_db`/`is_unique_violation_db` all have dozens of live callers; and the `Statement::from_sql_and_values` idiom itself (28 files), which is the deliberately-chosen mechanism for preserving hand-tuned SQL text verbatim while decoding by name, not a transitional artifact. `sqlx` itself is not deleted from the workspace outright — it remains in `hive-persistence`'s and `hive-api`'s `[dev-dependencies]` for their own test-fixture files, which never went through this port.

Documentation updates in `GSR-PHASE-P8`: `docs/rust-transformation-design.md` status section gains a paragraph stating `RTD-GENERATED-READ-TIER`, `RTD-TENANT-HOOKS`, `RTD-ENTITY-COVERAGE` are built and that the "verbatim SQL through sqlx" clause of the decision summary and the Repositories paragraph are superseded by this plan; `docs/rust-idiom-remediation-plan.md` marks `RIDR-FROM-ROW` and `RIDR-SEA-ORM-DEAD-DEPENDENCY` Done with this plan as the citation.
